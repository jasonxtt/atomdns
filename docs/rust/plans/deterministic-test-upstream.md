## 选型

推荐官方CoreDNS预编译Linux amd64二进制，固定v1.15.0和下载SHA256；禁止运行时自动更新。不安装Go工具链、不添加项目Cargo/Go依赖、不使用Docker镜像。

选择理由：file读取标准区域文件，template可固定answer/authority/additional及rcode；支持UDP/TCP和TLS/HTTPS/QUIC监听。hosts仅支持A/AAAA/PTR，不能独自覆盖复杂日志负载。dnsdist也可构造应答，但其DelayAction仅UDP，仍需额外机制统一控制多协议时延。本选择基于文档与现有需求，实际发布二进制的插件/协议能力必须安装后逐项自测。

## 部署与隔离

- 主机mos-test，已只读核实Debian13/x86_64/4CPU，tc已安装；约3.2GiB可用内存、磁盘剩余1.7GiB。CoreDNS尚未安装。
- 独立目录/opt/atomdns-test-upstream，保存版本二进制、配置、版本化fixtures、映射与控制脚本。私有应答人口和证书密钥不提交仓库；仓库保存生成器、合成样本、方案和公共哈希。
- 专用Linux网络namespace/veth；仅测试机内部可达的专属地址/端口。部署时探测冲突，绝不接管53/5533/现有服务端口或修改生产DNS。网络控制仅操作自建veth，不改变主网卡qdisc、默认路由、系统DNS或全局代理。
- 用专用systemd单元管理，提供start/stop/reset/check/status。持久保留安装和fixtures；性能运行前停止旧实例并按指定fixture重新启动，不继承旧连接或队列；开机默认不自动运行。
- 被测程序CPU0、sender CPU1、上游CPU2、采样CPU3；CoreDNS限制工作线程。监控上游CPU、排队、错误及网络丢包，证明当前速率下没有成为瓶颈。共享VM仍有调度/频率波动，不能声称物理上完全无噪声。
- 本机生成测试CA/证书，使用测试实例已有信任方式；不关闭证书校验，不写入生产信任配置。HTTPS/QUIC启动后实际验证ALPN、证书和会话复用行为。

## 固定应答与身份

1. 按域名/QTYPE/上游供应商ID生成版本化应答表和预期结果，不从公网查漏补缺；未知题返回明确约定的否定答案或使题库预检失败。
2. 上游不启用forward/cache/loadbalance/自动reload，不进行递归或后台公网刷新；标准区文件固定TTL、RR顺序与内容。测量前冻结配置/数据/二进制SHA256。
3. 覆盖A/AAAA、多地址、CNAME链、TXT/SRV/MX及其他所需RR、NXDOMAIN、NODATA、SERVFAIL、不同TTL、大应答和UDP截断/TCP回退。逐项建立预期，而不是认为CoreDNS启动成功就全部支持。
4. 为真实语料建立可重复的复杂度/记录多样性分布；不能所有名字只返回同一个IP，避免共享模板被过度去重、虚报审计内存收益。国内/国外/假IP等答案按现有业务分类和规则核对。不得未经核对就把atomdns已经改写的最终应答当作原始上游应答。
5. 每个原供应商保留独立ID及独立测试端点，保留组、协议、顺序、并发策略和代理路径（需要时保留本地可控代理）。不再将同组多个供应商合并为同一端点；只改测试副本的出站地址、测试证书/代理和隔离所需监听。
6. 同样的固定端点供BASE与候选交替使用；每角色运行前reset到同一fixture。请求原始DNS ID/Question原样对应；DNS ID、Trace ID和实际耗时不伪装成跨运行固定值。

## 延迟与故障档

CoreDNS负责标准DNS应答；Linux tc netem负责专用veth上的按端点区分的网络路径。其延迟作用于包，可能包含TLS握手，不能称为精确的服务器每查询处理时间。默认不加随机抖动/丢包，不能用CoreDNS erratic的每N条计数故障影响正常负载顺序。

- 快速性能档：主选端点无人工延迟；其他竞争端点使用足够分离的固定附加延迟（初拟30/80ms，资格验证前冻结）。固定值是设置值，真实收包时延仍需测量。
- 路由/回退档：按供应商明确设置快慢关系及独立标记答案，验证final_upstream、回退顺序及诊断。
- 故障档：专用配置或端点的SERVFAIL、NXDOMAIN、超时/关闭端口/丢包等，单独运行，不混入正常性能验收。畸形wire等CoreDNS不提供的专用故障继续使用现有mock，避免改造第三方服务或声称一个服务覆盖所有异常。

## 验收顺序

1. 固定版本和摘要，验证配置及端口隔离，实际检查UDP/TCP/DoT/DoH/DoQ。先覆盖当前生产副本用到的协议，再完成其余既有协议回归。
2. 对完整预定题库直接查询上游，核对Question/rcode/三节RR/TTL、顺序及各供应商身份；确认无公网出站、没有自动刷新、相同输入稳定。协议ID与客户端时间字段单独核对，不要求原始包字节机械相同。
3. 检查业务路径：保留当前完整配置/规则/容量；learner初始状态和自然过期边界明确，缓存分别以空/预热/固定负载状态测试。学习状态的并发与过期仍需原计划状态模型，固定上游不会自动解决这些问题；不修改last_seen、不延寿、不删难题，不接受错误多答案来蒙混过关。
4. 同一BASE二进制做三组BASE/BASE资格对照，固定CPU、语料、seed和负载，60s预热+300s测量，检查完整DNS/路由/learner预期以及既有5%CPU/尾延迟噪声界限。任何资格失败都不准归因于优化代码；保留数据，不跑到绿或修改阈值。
5. 资格通过且当前产品/方法审查完成后，才做原项目三组交替BASE/候选及最终2h。分别报告计划发包到收包、实际发送到收包、sender调度延迟；CPU按已验证正确查询计，同时保留所有错误/短缺/超时。启动/热应用/读取峰值单列；固定应答不能替代真实记录人口的堆门槛。
6. 所有负载前检查磁盘预算，原始数据写独立运行目录；不为腾空间删除已有证据或无关文件。每次保存源/二进制/fixture/映射/时延/题序指纹、上游计数、原始应答、资源及清理收据；未执行或不稳定项记未完成。
