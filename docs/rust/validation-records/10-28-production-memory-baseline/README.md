## 域名数量与内存的关系

影响内存的不只有日志条数，还包括域名长度、缓存键数量、应答内容及TTL差异、诊断详情、共享程度、学习/访问统计记录、规则规模，以及已释放但仍驻留的分配器页。

当前概览的域名数从保留日志读取时计算，没有为这个卡片额外常驻一张域名表。每条日志仍单独保存自己的域名；因此固定条数、相同长度时，增加不同域名不一定增加这部分字符串总量。不同名字通常还会形成更多缓存键、学习和访问统计条目，并可能降低应答共享率，所以整进程内存通常也会受影响，不能只按一个数字线性推算。

本次1338仅指当前10万条日志中的不同域名；缓存与学习表可保留更早的数据，并且各自口径不同。它们不能直接相加。

## 采集方法及读取影响

- 先读取版本、运行镜像、服务身份和选定磁盘输入指纹；按0.25秒间隔采样进程内存。
- 读取前等待10秒，然后顺序GET健康、捕获状态、日志总数、缓存目录、metrics、时间窗口、域名排行、最新日志样本、学习表状态，最后复查日志数和metrics。
- 域名排行仅请求 `limit=1`，计数来自同一响应的完整环统计头；返回的一条排行不是域名总数。
- 日志只抽取**最新500条**，记录类型、域名长度、RR数量、应答数据长度及TTL敏感的应答多样性。它们只描述样本，不代表全10万条，也不能换算保留堆大小。原始名字、客户端地址及应答留在私有文件中。
- GET结束后继续观察15秒，总时长25.39秒，共102个内存样本。采样最大RSS仍为95,696KiB；短峰值可能落在采样间隙，历史VmHWM不能充当本次读取峰值。
- 84个配置、规则及持久状态文件共4,340,148字节，采集前后及随后私有归档的内容指纹一致；归档不包含活缓存、进程堆、完整日志环、UI或系统外部输入，不能当原子进程检查点。

未执行DNS负载、清空、调整容量、保存、热应用、trim、暂停、重启或部署。进程PID/start ticks及服务身份保持一致，仓库产品代码未变。
